## 0. Why this analysis exists

The original bench compared LoopGain (LG) against **fixed-iteration-cap baselines** (`max_iter ∈ {5,10,20}`). It never compared LG's **stability-based** stop rule against the crowded field of **confidence-based** early-termination methods (entropy thresholds, PASR, DeepConf, REFRAIN's sliding-window-UCB bandit). The competitive question — set in `loopgain/wiki/syntheses/cost-leverage-landscape-and-stability-wedge.md` — is whether **stability** (a signal on the *dynamics* of the error trajectory) is a genuine edge over **confidence** (a signal on the *level* of the error / answer certainty), or whether the two are interchangeable on real loops.

This re-analysis answers that on already-captured per-iteration data. It also runs four diagnostic analyses on the per-iteration signal to test whether a stop decision based on it is *principled*.

---

## 1. The real signal being replicated (verified, not assumed)

The registered data was generated by **loopgain 0.2.0** (the version installed in `.venv/`, confirmed against the `loopgain_version` field in every JSONL header). 0.2.0 uses the **legacy single-feature classifier**:

- Per-iteration loop gain: `Aβ_n = E_n / E_{n-1}` (ratio of consecutive verifier errors).
- Smoothed: `Aβ_smooth` = EMA with `smoothing_window=3` (⇒ α = 2/(3+1) = 0.5).
- Band map (thresholds 0.3 / 0.85 / 0.95 / 1.05): `<0.3` FAST_CONVERGE, `<0.85` CONVERGING, `<0.95` STALLING, `≤1.05` OSCILLATING, `>1.05` DIVERGING.
- Terminal states: **TARGET_MET** (E ≤ `target_error`), **OSCILLATING**, **DIVERGING**, **MAX_ITERATIONS**. STALLING is non-terminal in 0.2.0.
- `gain_margin = 1 / max(Aβ_smooth)`.
- LG condition is run with `max_iterations=20` (ceiling) and the **per-cell** `target_error`.

**Per-cell `target_error` (verified from headers — load-bearing):**

| Cell family | `target_error` | Consequence |
|---|---|---|
| W1–W4 (codegen / debate / planner / RAG) | `0.0` | LG short-circuits on TARGET_MET when error hits 0. |
| **W5 (adversarial, all 3 adapters)** | **`None`** | **No target short-circuit.** Error *starts* at 0 and the loop degrades; LG must detect divergence purely from the band signal. W5 is therefore the cleanest test of the stability wedge — a confidence/level rule has no "done" signal to lean on either. |

**Replication fidelity (computed as a pre-flight integrity check, not a result of the claims below):** replaying the 0.2.0 `observe()` logic on each trial's recorded `LG.error_history`, with the correct per-cell `target_error` and `max_iterations=20`, reproduces the recorded `outcome`, `iters`, full per-iteration `state_history`, **and** `gain_margin` for **2,000 / 2,000 trials (100.00%)**. The replicated stop rule **is** the genuine product logic, so the counterfactual head-to-head below uses real behavior, not a reinvention. The 0.3.0 multi-feature trajectory classifier in `loopgain-core` is newer and did **not** generate this data; it is referenced only where Analysis 2 (jitter) motivates it.

## 2. Experimental design — counterfactual head-to-head on identical trajectories

`B20` is a **pure fixed-cap** condition: it always runs the full 20 iterations (no target short-circuit) and records the complete `error_history`. This is the ideal substrate: **both** stop rules are replayed on the *identical* unstopped B20 trajectory, so any difference is attributable to the stop signal alone.

Three rules are simulated per B20 trajectory (n = 2,000):

1. **STABILITY** (the product): the verified 0.2.0 LoopGain logic — `Aβ_smooth` bands, terminal on OSCILLATING/DIVERGING/TARGET_MET, per-cell `target_error`, `max_iterations=20`, **best-so-far buffer** (kept output = lowest error observed up to the stop).

2. **CONFIDENCE** (the baseline): a **patience / plateau** early-stop on the error *level* — the standard reduction of confidence-based early termination to a verifier-score setting. Stop at the first iteration where **either** (a) `E ≤ target_error` (same per-cell short-circuit as STABILITY — fairness), **or** (b) the best-so-far error has not strictly improved for **k** consecutive iterations ("confident no further gain is coming"). Same per-cell `target_error`, same `max_iterations=20` ceiling, **same best-so-far buffer**. **Primary `k = 2`; sensitivity reported for `k ∈ {1, 2, 3}`.**

   *Rationale that this is a fair, non-strawman analog:* entropy/PASR/DeepConf/REFRAIN all decide *when to stop* from a signal about the current answer's certainty, with no model of trajectory oscillation. Reduced to a verifier-error setting, "high confidence the answer is good / won't improve" **is** the no-strict-improvement-for-k-steps criterion. Both rules share the target short-circuit and the best-so-far buffer, so the **only** difference is the early-stop trigger: STABILITY keys on the **dynamics** (`Aβ_smooth` oscillation/divergence); CONFIDENCE keys on the **level** (plateau). Best-so-far rollback is held constant so it cannot advantage either rule.

3. **B20-FULL** (reference): runs to 20, kept output = best-so-far over all 20. Used as the savings denominator and the quality ceiling.

**Cost model (per trial, disclosed approximation).** Per-iteration tokens were not recorded; per-condition totals were. For each trial, fit `cost($) = a + b·iters` by least squares to the three recorded baseline points `(5, $B5), (10, $B10), (20, $B20)`, where each `$Bn` is recomputed from that condition's `input_tokens`/`output_tokens` against the frozen `prices.json` (2026-05-21). Estimated cost of stopping at `k` iterations = `a + b·k` (clamped to ≥ the 1-iter cost). Iterations-saved is reported as the **exact, primary** unit; token-$ savings is the secondary unit using this per-trial linear model. Any trial where the staircase is degenerate (e.g. all three baseline costs equal) falls back to a uniform `$B20/20` per-iteration cost, and the count of such trials is disclosed.

**Quality metric (per trial).** Kept-output error under a rule = `min(error_history[0 : stop_index+1])` (best-so-far). Lower is better. To compare across cells with different error scales, errors are normalized per cell by that cell's `E_first` percentile scale (disclosed in results); the paired *difference* `kept_err_stability − kept_err_confidence` is the quantity tested.

All statistics use **paired-by-trial bootstrap** (10,000 resamples, resampling trials with replacement), seeded deterministically (`numpy` default_rng(20260531)) for reproducibility. No scipy/statsmodels is available; all tests are implemented in numpy/stdlib and the method is stated inline.

## 3. CLAIM 1 (pre-registered, falsifiable) — Stability beats confidence on savings at matched quality

> **A stability-signal stop rule achieves token/$ savings that beat a confidence/plateau baseline operating at matched quality.**

Reference range from the literature for confidence-based methods: **~20–55% token savings** vs a fixed budget. Both rules are reported as **% token-$ saved vs B20-FULL**, overall and split by workload family (W1–W4 natural-distribution vs W5 adversarial).

**Exact decision rule** (let `S_stab`, `S_conf` = per-trial % token-$ saved vs B20; `ΔS = S_stab − S_conf`; `ΔQ = kept_err_stability − kept_err_confidence`, normalized):

- **PASS (stability beats confidence)** iff **all three** hold:
  1. `mean(ΔS) ≥ +5.0 percentage points` (stability saves materially more), **and**
  2. the 95% paired-bootstrap CI on `mean(ΔS)` **excludes 0**, **and**
  3. **quality non-inferiority**: the **upper** 95% paired-bootstrap CI bound on `mean(ΔQ)` ≤ **+0.05** normalized error units (stability is not meaningfully worse on quality — it did not buy savings by stopping too early and degrading the kept output).
- **NULL → HYBRID** iff savings are statistically indistinguishable at matched quality: `|mean(ΔS)| < 5.0 pp` **or** the CI on `mean(ΔS)` includes 0, **while** quality non-inferiority (3) holds. Per the task framing, the honest finding here is **"ship a hybrid (stability + confidence)"** — a valid, valuable result, not a hidden failure.
- **FAIL** iff stability is significantly *worse* on savings (`mean(ΔS)` CI entirely below 0) **or** quality inferiority (upper CI on `mean(ΔQ)` > +0.05 — stability degraded quality to buy savings).

The overall verdict is reported; the per-family verdict (esp. W5, where the wedge is hypothesized to concentrate) is reported alongside and **cannot** be used to overturn a null overall verdict after the fact.

## 4. CLAIM 2 (pre-registered, falsifiable) — Oscillation detection catches unique waste

> **The oscillation-detection signal catches a material share of the wasted iterations a confidence-only method lets run** — loops a confidence/plateau rule would keep running but that are oscillating and should be stopped.

**Definitions** (computed on the same n = 2,000 B20-trajectory simulations):

- **Wasted iteration under CONFIDENCE** = an iteration the CONFIDENCE rule executed that came *after* it had already observed its kept-best output (pure cost, zero quality gain). For each trial: `wasted_conf = stop_conf_iters − (argmin_index_of_error_in[0..stop_conf) + 1)`, clamped ≥ 0. Denominator `W_total = Σ_trials wasted_conf`.
- **Iterations uniquely caught by OSCILLATION detection** = for trials where (a) the STABILITY terminal state is specifically **OSCILLATING** (not DIVERGING, not TARGET_MET) **and** (b) `stop_stab_iters < stop_conf_iters`: the count of cut iterations in `[stop_stab, stop_conf)` that do **not** set a new running-best (i.e. genuinely wasted, so cutting them costs no quality). Numerator `U_osc = Σ` of those.

**Metric**: `U_osc / W_total`.

**Exact decision rule:**
- **PASS** iff `U_osc / W_total > 15%` (the strict end of the 10–15% reference band).
- **WEAK PASS** iff `10% < U_osc / W_total ≤ 15%` (clears the loose end only) — reported as a qualified pass.
- **FAIL** iff `U_osc / W_total ≤ 10%`.

For context (not part of the claim), the same numerator computed for **DIVERGING**-terminal trials and for **all stability-terminal** trials will be reported, plus `W_total` split by workload family. The claim is specifically about the **OSCILLATING** band, per the wedge hypothesis.

## 5. Four diagnostic analyses (characterizations, with stated "principled" criteria)

These are not pass/fail claims, but each states what a *principled* signal looks like so the reader can judge.

**A1 — Within-run stationarity.** Per run, test whether the loop-gain signal is stationary enough that a band-based stop is principled vs noise. Methods (numpy/stdlib, no statsmodels): (i) distribution of the **detrended log10(E) residual std** (`osc_std`, the actual 0.3.0 feature) per run; (ii) per-run **lag-1 autocorrelation** of the `Aβ` series; (iii) **first-half vs second-half** mean/variance split (variance-ratio) for runs with ≥ 6 iterations; (iv) a **runs/sign test** on the first differences of log10(E). *Principled* ⇒ the per-step signal is not dominated by noise: report the per-run signal-to-noise `|mean step| / std(step)` distribution and the fraction of runs where the trend is distinguishable from a random walk. Short runs (the converge-fast majority) are reported separately from the ≥ 6-iter tail (the interesting cases).

**A2 — Step-jitter.** Distribution of iteration-to-iteration jitter `|ΔAβ|` and `|Δ log10 E|`. Re-run the STABILITY stop rule with EMA smoothing windows `{1, 3, 5, 7}`; for each, measure (i) how the stop iteration shifts, (ii) **premature stops** (stop before the trajectory's global-best index is reached), and (iii) **late stops** (stop ≥ 2 iters after global-best). Report how much smoothing is needed before the stop iteration stabilizes (changes in < 5% of trials when the window is increased further). This connects directly to why 0.3.0 moved to a multi-feature trajectory classifier.

**A3 — Cross-framework consistency.** Per-framework distributions (LangGraph, CrewAI, AutoGen, LangChain, OpenAI Agents, Claude Agent SDK) of: stop-iteration, LG outcome mix, `gain_margin`, `osc_std`. Test signal-behavior consistency with a **Kruskal–Wallis H** (numpy implementation, ranks) across frameworks *within a matched workload*: W5 across {bare, LangGraph, CrewAI} and W1 {LangGraph vs Claude Agent SDK}. Specifically test whether a signal-level difference correlates with / explains the **5.8 pp W1 framework-parity spread** that `RESULTS.md` disclosed as a missed floor (predicted ≤ 5 pp).

**A4 — Early-warning lead time (re-measured precisely, full distribution).** For each B20 trajectory with a **degrade event** — first iteration `D` after the global-best index where error rises above the running best by ≥ 1 error unit — compute the **lead** = `D − (first iteration the stability rule emits a warning band STALLING/OSCILLATING/DIVERGING on the B20 prefix)`. Report the **full distribution**: histogram, median, mean, quartiles, and the fraction with lead `≥ 1, ≥ 2, ≥ 3`, **and the fraction ≤ 0** (warning fires at-or-after the degrade = too late). The fraction `≤ 0` is the empirical surfacing of the **"wrong-fixed-point / kill-a-near-success-loop"** risk and the thin-margin concern (`RESULTS.md` reported median lead 2 vs ≥ 3 predicted; kill threshold < 1 survived but the margin is thin). This re-measure must reconcile with that median-2 finding or explain the difference.
